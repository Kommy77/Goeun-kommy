# PRD — FreshKeeper (MVP → 지인 100명 실서비스 확장)

## 1. Summary

FreshKeeper는 냉장고 재료를 등록하면 유통기한을 알려주고, 재료로 만들 수 있는 레시피를 추천해주는 서비스입니다. 지금은 로그인도 없고, 사진 인식도 안 되고, 레시피도 몇 개 안 되는 껍데기 MVP 상태입니다. 이 문서는 이걸 지인 100명이 실제로 매일 쓸 수 있는 수준으로 만들기 위한 다음 단계를 정리합니다.

## 3. Background

FreshKeeper는 v0류 AI 툴로 빠르게 만든 MVP를 Vercel에 배포한 상태입니다. 코드를 GitHub로 옮기고 로컬에서 돌려보는 과정에서, 실제로는 다음이 확인됐습니다.

- **로그인이 없습니다.** Supabase 데이터베이스 접근 권한(RLS)이 전체 공개로 열려 있어서, 지금은 누가 접속하든 똑같은 데이터 한 세트를 보고 씁니다. 지인 여러 명이 동시에 쓰면 바로 데이터가 섞입니다.
- **랜딩페이지의 핵심 약속이 실제로는 없습니다.** "냉장고 사진으로 시작하기" 버튼을 누르면 사진 인식 없이 그냥 손으로 입력하는 화면으로 넘어갑니다.
- **레시피 추천이 가짜입니다.** 코드 안에 레시피 2~3개가 그대로 박혀 있고, 사용자가 가진 재료와 실제로 비교해서 추천하는 로직이 없습니다.

지금 이 문서를 쓰는 이유는, "일단 지인들한테 링크 뿌려보자" 하기 전에 최소한 **각자 자기 데이터를 보게 만들고**, **광고한 기능 중 하나라도 실제로 작동하게** 만들기 위해서입니다.

## 4. Objective

**목표**: 지인 약 100명이 각자 자기 냉장고 데이터를 가지고, 실제로 재료를 등록하고 유통기한 알림을 받고 레시피를 추천받는 걸 최소 2주 이상 반복해서 쓰게 만든다.

이 프로젝트는 사업화나 투자가 목적이 아니라, "내가 만든 게 실제로 남들에게 쓸모 있는가"를 검증하는 단계입니다. 결제는 이번 범위에 넣지 않습니다.

**성공 기준 (Key Results)**
- KR1: 초대한 지인 중 40% 이상이 최초 1회 이상 재료를 등록한다 (가입만 하고 떠나는 게 아니라 실제 사용)
- KR2: 그중 50% 이상이 2주 뒤에도 재료 데이터가 남아있고 최소 1회 이상 갱신(추가/삭제)한다 (데이터가 방치되지 않고 살아있는지)
- KR3: 유통기한 임박 알림을 본 사용자 중 30% 이상이 그 재료를 "삭제"(소비 처리)한다 (알림 → 행동으로 이어지는지, 데이터가 실제 냉장고와 맞는지의 간접 지표)

## 5. Market Segment(s)

**대상**: 자취하거나 요리를 어느 정도 하는 20~30대 지인/가족. 냉장고 재료를 잊어버려서 버린 경험이 있는 사람.

**제약**
- 개발자는 1명(본인)이고, 부업/사이드 프로젝트 페이스로 진행합니다.
- 서버/AI API 비용을 개인이 감당할 수 있는 수준으로 유지해야 합니다.
- 사용자 대부분 비개발자이므로, 회원가입·사진 촬영 같은 절차가 조금이라도 번거로우면 바로 이탈합니다.

## 6. Value Proposition(s)

| 사용자가 겪는 문제 | FreshKeeper가 주는 것 |
|---|---|
| 냉장고에 뭐가 있는지 몰라서 장을 또 본다 / 재료를 썩힌다 | 재료 목록 + 유통기한 임박 알림 |
| 뭘 해먹을지 매번 고민한다 | 가진 재료로 만들 수 있는 레시피 추천 |
| 재료 입력이 귀찮아서 안 쓰게 된다 | 영수증 찍기 / 말하듯 입력하기로 등록 시간 단축 |
| 내 데이터가 남들과 섞이는 게 불안하다 | 로그인 기반으로 내 냉장고만 나에게 보임 |

경쟁 상대는 다른 앱이 아니라 **"그냥 기억하거나 카톡 메모장에 적는 것"** 입니다. 이 방식보다 확실히 쉬워야 사람들이 갈아탑니다.

## 7. Solution

### 7.1 UX/Prototypes

현재 화면 흐름은 유지합니다: 랜딩 → (로그인) → 홈(재료 목록) → 재료 추가 → 레시피 목록. 추가되는 것은 로그인/회원가입 화면 1개, 재료 추가 화면에 "영수증으로 등록" / "말로 등록" 탭 2개입니다.

### 7.2 Key Features (우선순위 순)

**① 로그인 및 내 냉장고 분리**
- 이메일 매직링크로 로그인합니다. 비밀번호를 만들거나 외울 필요가 없습니다.
- 로그인한 사람마다 "내 냉장고" 공간이 따로 생기고, 그 안의 재료만 나에게 보입니다.
- 지금은 냉장고 하나에 나 혼자만 접근하지만, 데이터 구조는 나중에 가족/룸메이트를 초대해서 같이 쓸 수 있게 여지를 남겨둡니다 (이번 범위는 아님).

**② 재료를 더 쉽게 등록하기**
- 영수증 사진을 찍으면 산 물건 이름과 산 날짜를 자동으로 읽어옵니다. 사람이 읽고 "이거 맞아요?" 확인한 뒤에만 저장합니다 (자동으로 바로 저장하지 않음).
- "오늘 계란이랑 우유 샀어" 처럼 말하듯 텍스트로 입력해도 재료로 등록됩니다.
- 재료 이름마다 "이건 보통 냉장 보관, 유통기한 약 7일" 같은 기본값을 미리 넣어둬서, 사용자가 유통기한을 모를 때도 자동으로 채워줍니다.
- 사진으로 냉장고 안을 통째로 인식하는 기능과 바코드 스캔은 이번 범위에 넣지 않습니다.

**③ 레시피 추천이 실제로 작동하게 만들기**
- 코드에 박혀있던 레시피를 데이터베이스로 옮겨서, 나중에 레시피를 추가하기 쉽게 만듭니다.
- 내가 가진 재료와 각 레시피 필요 재료를 실제로 비교해서 "몇 % 일치하는지" 계산합니다.
- 유통기한이 임박한 재료를 쓰는 레시피를 우선 보여줍니다 (음식 낭비를 줄이는 목적과 직접 연결).
- AI가 알아서 레시피를 만들어주는 기능, 사용자가 직접 레시피를 올리는 기능은 이번 범위에 넣지 않습니다. (이유: 지인 100명 규모에서는 올리는 사람이 적어서 텅 비어 보일 위험이 큽니다.)

### 7.3 Technology

- 프론트엔드/DB는 지금 쓰는 것(Vite+React, Supabase)을 그대로 유지합니다.
- 로그인은 Supabase에 내장된 인증 기능을 사용합니다.
- 영수증 사진 읽기와 문장 이해는 AI(LLM) API를 서버 쪽에서 호출해서 처리합니다 (API 키가 사용자 화면에 노출되지 않도록).

### 7.4 Assumptions & Risks (검증 안 된 가정과 위험)

먼저 짚은 가정들을 반론으로 점검한 결과, 아래가 남은 위험입니다. 팀(=본인)은 이걸 알고 진행하는 것이며, 출시 전/후로 계속 확인해야 합니다.

| 가정 | 왜 위험한가 | 어떻게 확인할까 |
|---|---|---|
| 재료를 다 먹거나 버리면 사용자가 앱에서 직접 지울 것이다 | **가장 치명적인 위험.** 등록은 쉬워져도 "다 먹었다"는 여전히 사람이 손으로 지워야 합니다. 사용자가 안 지우면 유통기한 알림이 계속 틀리게 되고, 몇 번 틀리면 신뢰를 잃고 앱을 떠납니다. | KR3 지표로 추적. 만약 삭제율이 낮으면, 다음 단계에서 "이거 아직 있어요?" 하고 주기적으로 물어보는 기능을 우선순위로 올립니다. |
| 영수증 사진이 냉장고 재료를 대표한다 | 영수증은 "방금 산 것"만 찍힙니다. 원래 있던 재료, 텃밭/시장에서 산 것, 선물 받은 재료는 영수증이 없어서 등록이 안 됩니다. | 초기 사용자 인터뷰에서 "영수증 없는 재료를 얼마나 등록하려 하는지" 확인. 필요하면 텍스트 입력 비중을 더 키웁니다. |
| 로그인을 추가해도 지인들이 그대로 써준다 | 지금은 링크만 열면 바로 쓸 수 있는데, 로그인이 생기면 그 첫 진입 장벽 때문에 안 써볼 수 있습니다. | KR1(최초 등록률)로 확인. 40% 밑으로 떨어지면 매직링크 대신 더 가벼운 방식(예: 이름만 입력)도 고려합니다. |
| 재료-냉장고 공유 구조를 미리 만들어두는 게 맞는 투자다 | "가족 공유"가 실제로 필요한 니즈인지 아직 검증 안 됐습니다. 반대로 "친구끼리 레시피 공유"가 더 필요할 수도 있습니다. | 이번 범위에서는 구조만 열어두고 기능은 안 만듭니다. 실사용 피드백 보고 어느 쪽을 만들지 나중에 결정합니다. |
| 지금 있는 레시피 몇 개로도 충분히 쓸만하다 | 레시피 수가 너무 적으면 매칭 로직을 아무리 잘 만들어도 맨날 같은 추천만 나옵니다. | 레시피 수를 최소 30~50개로 늘리는 작업을 ③ 착수와 같이 병행합니다 (직접 정리 또는 외부 레시피 자료 참고). |

## 8. Release

사업/투자 단계가 아니므로 정확한 날짜 대신 순서로 표현합니다.

**1차 (이번 범위)**
- ① 로그인/내 냉장고 분리
- ② 영수증 OCR + 텍스트 빠른입력
- ③ 실제 작동하는 재료-레시피 매칭 + 임박재료 우선순위, 레시피 최소 30개 이상 확보

**2차 이후 (이번 범위 아님, 필요성 검증되면 진행)**
- 냉장고/가구 단위 공유 (초대 링크)
- 소비/폐기 빠른 체크(스와이프 등)로 데이터 정합성 개선
- 냉장고 사진 통째로 인식, 바코드 스캔
- 사용자가 직접 레시피 올리기(UGC)
- 결제/유료 플랜
